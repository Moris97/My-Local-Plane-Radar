## Data

| Dataset | License | Notes |
|---|---|---|
| Natural Earth 1:10m (coastline, borders, rivers, major cities) | Public domain | Fetched by `scripts/fetch-mapdata.sh` from the [martynafford/natural-earth-geojson](https://github.com/martynafford/natural-earth-geojson) mirror (repo itself CC0-1.0), which pre-converts Natural Earth's shapefiles to GeoJSON. The script strips unused attributes, rounds coordinates to 4 decimal places, and filters rivers/cities by `scalerank` before writing to `data/naturalearth/` (~12 MB total, never committed). Used for the **offline** basemap mode. |
| OpenFreeMap vector tiles (`https://tiles.openfreemap.org`) | ODbL (data) / BSD-3-Clause (OpenMapTiles schema, CC-BY tiles service) | Not an npm package — a map tile/data source, requested directly by the browser via MapLibre GL JS (already a dependency), no API key or account needed. Used for the **online** (default) basemap mode. Our own style (`public/mapstyles/online-dark.json`) references their `openmaptiles` vector source and glyph server; we do not use their ready-made liberty/positron/bright styles. **Attribution must name all three parties**, per [OpenFreeMap's own quick-start docs](https://openfreemap.org/quick_start/): "OpenFreeMap © OpenMapTiles Data from OpenStreetMap" (each name linked individually). Shown as a small custom-styled credit (`#mlpr-attribution`), visible only in online mode — offline mode uses Natural Earth (public domain), which needs none of this. An earlier version of this credit said only "© OpenStreetMap contributors", missing the OpenFreeMap and OpenMapTiles names — fixed 2026-07-28. |
| Planespotters Photo API (`https://api.planespotters.net/pub/photos/hex/{hex}`) | Free public API, own [Terms of Use](https://www.planespotters.net/photo/api) (not an OSS license) | Not an npm package — fetched directly by the browser (`public/js/aircraft-panel.js`) when the aircraft details panel is opened, keyed by ICAO hex. No API key. Terms re-checked 2026-07-28 against the current page (their photo API is explicitly designed for exactly this shape of use — many independent installs, each end user's own browser calling the API directly — not something we need to ask special permission for). What their terms require, and how MLPR meets each one: **browser clients must request from a page that sends an `Origin`/`Referer` header** (automatic — every real fetch from our page satisfies this; this is also *why* the call is browser-side and never proxied through our own Fastify server, since server-to-server calls need a descriptive `User-Agent` + contact info instead, which we'd rather not maintain); **photographer credited in text next to the image, thumbnail linking unmodified to the `link` URL, no `rel="nofollow"`** (the "Photo: {photographer}" line and the image both link to the API's own `link` value as-is); **image binaries loaded by the end user's browser from `thumbnail_large.src`, never downloaded/stored/re-hosted/proxied by us** (true — we only ever set `<img src>` to their CDN URL); **not an exclusive/paid feature, same thumbnail size for everyone** (true, it's just a panel in a free app); **API responses may be cached "on your servers" for up to 24h** — read literally as being about server-side infrastructure, which doesn't apply here since our Fastify backend never touches this API at all; `public/js/photo-cache.js` instead caches results in the *end user's own browser* (`localStorage`, a hit kept indefinitely, a miss for 7 days, capped at 3000 entries) purely so that one browser doesn't re-ask about an aircraft it already looked up — this reduces Planespotters' load rather than mirroring/re-exposing their data to anyone else. This is a judgment call on a clause written with server-side infrastructure in mind, not client-side browser storage — flagged to and confirmed with the project owner (2026-07-28) rather than assumed unilaterally; revisit if Planespotters' terms are ever updated to explicitly address client-side caching. Graceful degradation: no photo found, or the fetch failing for any reason, just omits the photo section — never an error shown to the user. Settings → Aircraft has a "Fetch aircraft photos" toggle (default on) to disable this external call entirely, since MLPR otherwise works fully offline. |
| [wiedehopf/tar1090-db](https://github.com/wiedehopf/tar1090-db) `aircraft.csv.gz` (aircraft registration/type database, sourced from [Mictronics](https://www.mictronics.de/aircraft-database/)) | No LICENSE file in the repo — distributed openly by readsb's own maintainer specifically as the documented `--db-file` source (see readsb's README), the standard way essentially every ADS-B hobbyist project gets this data. Not a code dependency; only concern here is *our* redistribution, and we don't redistribute it — it's fetched onto the *user's own* readsb install, same as they'd do manually per upstream's own instructions. | Not fetched by MLPR itself — `scripts/install.sh` downloads it to `/usr/local/share/tar1090/aircraft.csv.gz` and wires it into readsb's own `--db-file` flag (readsb is a separate process/service, not part of this repo). Without it, readsb never reports registration/aircraft-type/dbFlags for any aircraft, which silently breaks parts of the aircraft details panel and notifications. Best-effort and idempotent, see CLAUDE.md's "Production deployment" section. |
| [OpenFlights](https://openflights.org/data.php) `airlines.dat` | ODbL-1.0 (data). OpenFlights' own website/code is AGPL — **we only ever use the data file, never their code**, so the AGPL is not in play here. | Fetched by `scripts/fetch-airlines.mjs` (hand-written CSV parser, no new dependency, same pattern as `fetch-mapdata.sh`) from the raw file in [jpatokal/openflights](https://github.com/jpatokal/openflights), filtered to active airlines with a non-empty ICAO code, written to `data/airlines.json` (`{icao: {name, country}}`, ~12 MB source reduced to a small JSON map, never committed — `data/` is already in `.gitignore`). Called from `install.sh` alongside the basemap fetch step, best-effort. Used to resolve a callsign's 3-letter ICAO prefix to an airline name for the "most common airline" chart — see CLAUDE.md's "Advanced statistics" section. ODbL requires attribution for the data: a small "Airline data: OpenFlights (ODbL)" credit line is shown in the Stats view. Never commit airline logos (trademark risk) — the charts use plain color swatches, not logos. |
